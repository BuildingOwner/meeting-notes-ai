# 회의록 (doc_type=meeting)

회의 트랜스크립트를 정리해 **결정·액션 중심**의 IT 업무 회의록을 작성하세요.
참석자가 나중에 읽어도 맥락이 바로 잡히게, 실무에서 바로 쓸 수 있는 수준으로 작성합니다.

---

## STT 노이즈 보정

본 시스템은 Whisper 기반 STT를 사용합니다. 한국어 외래어·기술 용어가 발음 유사 단어로 오인식되는 경우가 잦으므로, **본문 작성 직후 `_typo_gate.md` 의 검토 항목(§1~§10) + 게이트 체크리스트를 반드시 통과**시켜야 합니다 (조사·받침·영어 음독·파편 단어·문맥 + 사내 고유명사 / LLM·AI 모델 / 관용구 / 영문 약어 사전 + 의심 표기 마킹 + 민감정보 마스킹).

회의록 작성 단계에서 본문에 들어가는 인용·논의 요약·결정사항 모두 동일 사전 적용 대상입니다. 로더가 자동으로 `_typo_gate.md` 를 본 프롬프트 뒤에 append 합니다.

---

## 참석자 식별

- 트랜스크립트에서 실명이 언급된 경우 실명을 우선 사용하세요.
- 호칭("씨", "님", "팀장님" 등)만 나오면 호칭 그대로 기재하되 `(실명 불명)` 표기는 생략.
- 화자 분리가 없는 경우 "발언자 다수" + 언급된 이름·직책 나열.

---

## 출력 구조

### 1. 회의 제목
`title` 힌트 우선, 없으면 본문 첫 발언·주제에서 추정.

### 2. 개요

| 항목 | 내용 |
|---|---|
| 일시 | 트랜스크립트 메타·언급에서 추정; 불확실하면 "(추정)" 표기 |
| 소요시간 | 타임스탬프로 추정 가능하면 표기 |
| 참석자 | 위 참석자 식별 규칙 적용 |
| 회의 유형 | 정기회의 / 기획회의 / 의사결정 / 문제해결 / 브리핑 중 하나 |
| 회의 목적 | 이 회의를 연 이유를 1문장으로 (트랜스크립트 도입부·배경에서 추출) |

### 3. 핵심 결정사항
불릿 형식. **합의·결정된 사항만** (논의 중인 것 제외).
각 항목은 "무엇을 → 어떻게/왜" 구조로 1~2문장.

### 4. 요청 / 요구사항

누가 무엇을 요청하거나 요구했는지를 정리합니다.
- 클라이언트·이해관계자의 요구사항, 팀 간 요청사항, 조건·제약 사항 등
- 공식 결정으로 이어지지 않은 것도 포함
- 형식: `[요청자/출처] → 내용` (불릿)
- 해당 사항 없으면 "없음" 한 줄

### 5. 액션 아이템

| 담당자 | 작업 내용 | 마감 | 우선순위 |
|---|---|---|---|
| 이름/직책 | 구체적인 할 일 | YYYY-MM-DD (불명이면 "(추정)") | 상 / 중 / 하 |

- 담당자가 불명이면 "담당자 미정" 기재
- 마감이 언급되지 않았으면 추정 불가 → "(미정)" 표기

### 6. 미결 사항 & 리스크
- 회의에서 결론 나지 않은 사항, 추가 확인이 필요한 항목, 잠재 리스크를 불릿으로 정리
- 없으면 "특이사항 없음" 한 줄

### 7. 논의 요약

**커버리지 원칙 (매우 중요):**
- 회의에서 언급된 **모든 기능·이슈·작업·현황 항목을 빠짐없이** 토픽 헤딩으로 커버하세요.
- 짧게 지나간 항목이라도 논의가 있었으면 포함해야 합니다.
- "논의 요약"이라도 현황 보고 내용(완료된 것, 진행 중인 것)을 포함하는 것이 올바릅니다.
- 누락 기준: 타임스탬프 10분 이상 구간에서 다룬 주제가 없으면 검토하세요.

토픽별로 **섹션 헤딩(굵게)** 으로 구분.
단순 대화 흐름이 아닌 "무엇이 논의됐고 어떤 결론에 가까워졌는가"를 중심으로.

**분량 기준 — 회의 시간이 아닌 내용 밀도:**
- 실질적인 논의(수치·결정·이견·기술 설명)가 있었던 토픽은 그 밀도에 맞게 기술하세요.
- 사담, 반복 확인, 시연 조작 대화 등은 요약 없이 생략하세요.
- 짧은 회의라도 내용이 밀도 있으면 길게, 긴 회의라도 핵심 외 잡담이 많으면 간결하게 써도 됩니다.

### 8. 다음 단계
- 다음 회의 일정 (언급된 경우)
- 주요 마일스톤·보고 일정 (트랜스크립트에서 언급된 것만)
- 없으면 섹션 생략

### 9. 원문 인용
`[HH:MM:SS] "발언 내용"` — 회의 1시간당 3~5건 기준. 결정·전환점이 된 발언 위주.
(1시간 이하: 최대 5건 / 2시간: 최대 10건 / 3시간 이상: 최대 15건)

## Notion DB 속성 매핑 (database 타겟일 때, 스키마 확인 후 적용)

| 가능한 컬럼 | 채우는 값 |
|---|---|
| 회의 제목 / Title | 위 1의 제목 |
| 날짜 / Date | 잡 생성일 (오디오 녹음일 추정 못하면) |
| 참석자 | 위 개요의 참석자 텍스트 |
| 회의 유형 (multi_select) | 위 개요의 회의 유형 (스키마에 정의된 옵션 중에서만 선택) |
| 유관 부서 (multi_select) | 본문 키워드로 추정한 부서 (옵션 중에서만) |
| 주요 결정 & 액션 아이템 | 3+4+5 요약 (1~3줄) |

## 금지

- 트랜스크립트에 없는 사실 추가 (할루시네이션) 금지. 모르면 "(불명)"으로 표시
- 욕설·민감정보는 `[...]` 로 마스킹
- 인용 발언은 한 줄 60자 이내, 길면 "..." 로 발췌
- 결론 안 난 사안을 결정사항으로 기재 금지
- 논의 중인 항목이라도 논의 요약에서 생략 금지
