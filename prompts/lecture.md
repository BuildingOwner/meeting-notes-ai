# 강의 노트 (doc_type=lecture)

강의 트랜스크립트를 정리해 **학습자가 복습·적용 가능한** 구조화된 노트를 작성하세요.
강사의 설명 흐름을 따르되, 강의를 못 들은 사람이 이 노트만으로 이해할 수 있는 수준까지 **재구성**합니다.
분량을 줄이는 것이 목적이 아니라, 잡음을 걷어내고 설명을 복원하는 것이 목적입니다.

`_base.md` 의 **밀도 규약**(요약이 아니라 재구성)과 **서식 규약**(가독성)이 이 문서에도 그대로 적용됩니다.

---

## STT 노이즈 보정 (필독)

이 시스템은 Whisper 기반 STT를 사용합니다. 한국어 외래어·기술 용어가 발음 유사 단어로 오인식되는 경우가 잦습니다.

**보정 원칙:**
- 문맥상 어색한 단어가 있으면 발음이 비슷한 기술 용어로 재구성하세요.
- 확신하기 어려우면 `(추정)` 표기 후 원문을 `[]` 안에 병기하세요.
- 인명·기관명·제품명·브랜치명은 문맥으로 최대한 복원하세요.

**흔한 오인식 패턴 예시:**
| 오인식 | 실제 의도 가능성 |
|--------|----------------|
| 산트로픽, 안트로픽 | Anthropic |
| 엔이전트, 애이전트 | 에이전트 (Agent) |
| 훈 | Hook |
| 콸스텍스트, 콘테스트 | 콘텍스트 (Context) |
| 레그 | RAG (Retrieval-Augmented Generation) |
| VLL | VLLM |
| 플래시 어텐션 | Flash Attention |
| QN, 큰, 쿤 | Qwen (LLM 모델명) |
| 젬마, 제마 | Gemma (LLM 모델명) |

이 표는 예시이며, 다른 용어도 동일한 판단으로 복원하세요.

**인명은 `_people.md` 의 팀 참석자 사전이 정답입니다.** 강사·질문자가 사전의 인물과 발음이 비슷하면 사전의 실명으로 복원하세요. 사전에 없는 외부 강사는 들린 대로 쓰되 확신이 없으면 `(불명)`.

## 출력 구조

### 1. 강의 제목
`title` 힌트 우선, 없으면 본문 도입에서 추정.

### 2. 개요

| 항목 | 내용 |
|---|---|
| 일시 | 트랜스크립트 메타·언급에서 추정; 불확실하면 "(추정)" 표기 |
| 소요시간 | 타임스탬프로 추정 가능하면 표기 |
| 강사 | 단서·메타에서 추정 (불명이면 "(불명)") |
| 회차 | "N번째 세션" 언급 있으면 표시 (불명이면 생략) |
| 주제 | 한 줄 요약 |
| 선수 지식 | 강사가 언급한 "미리 알아야 할 것" 또는 본문에서 전제하는 개념 (없으면 생략) |

### 3. 학습 목표
강사가 명시한 목표 또는 본문에서 추론한 학습 결과 **3~5개 불릿**.
"이 강의를 마치면 ___를 할 수 있다" 형태로 작성.

### 4. 핵심 포인트 요약
강의에서 반드시 기억해야 할 개념·원리 **5~7개 불릿**.
- 각 불릿은 1문장, 시험·실무에서 바로 활용 가능한 형태
- 개념 정의가 아닌 "이것이 왜 중요한가"를 담을 것

### 5. 개념 정리

| 개념 | 정의 | 예시 / 비고 |
|---|---|---|
| 개념명 | 강사가 제시한 정의 (임의 수정 금지) | 강의 중 언급된 예시나 맥락 |

신규 개념·중요 용어 위주. 없으면 섹션 생략.

### 6. 강의 내용 정리 (가장 풍부해야 하는 섹션)

강의 흐름대로 `### ` 챕터 헤딩으로 구분. 각 챕터는 아래 6단 구조로 풍부하게 재구성합니다. 한 챕터당 본문 분량은 **최소 200~400자**, 정보 밀도 높으면 더 길게.

#### 챕터 템플릿

```markdown
### 챕터 N. {챕터 제목}

**핵심 메시지** (1~2문장)
> 이 챕터가 학습자에게 전달하려는 단 하나의 결론.

**상세 설명** (5~10문장)
강사 설명을 학습자가 읽기 좋게 재구성. 추임새·반복 제거, 논리 순서 정돈. 강사의 표현·강조 어조는 보존하되 문어체로 변환. 강사가 비유·은유로 설명했으면 그 비유를 보존.

**예시·수치·데모**
- 강사가 든 구체 예시 보존: 회사 사례, 수치, 그래프 설명, 코드 예시
- 라이브 데모가 있었으면 입력·출력 흐름을 단계별로 정리
- 코드 블록 / 표 / 의사 코드 등 강사가 보여준 형태로 재현

**시각 자료 / 코드**
강사가 슬라이드·코드·다이어그램을 언급한 부분은 마크다운 코드블록 또는 표로 재현. 슬라이드 텍스트를 받아쓴 부분도 포함.

> **강사 강조**: "이건 시험에 나옵니다 / 실무에서 자주 틀리는 부분이에요" 류의 강조 발언을 인용 블록으로 보존 (`[HH:MM:SS]` 포함).

**자주 헷갈리는 점 / 함정** (있으면)
- 강의 중 학습자가 질문했거나 강사가 "이거 헷갈리시는 분들 많은데" 류로 짚은 포인트
- 인접 개념과의 혼동, 자주 하는 오해
```

> **분량 가이드**: 30분 강의면 챕터 3~5개, 1시간이면 5~8개, 2시간이면 8~12개. 챕터를 너무 잘게 쪼개지 말고 강사가 만든 자연스러운 흐름 단위로.

### 7. Q&A 정리

강의 중 학습자 질문·강사 답변이 있으면 정리. 없으면 섹션 생략.

각 Q&A 는 아래 형식:

```markdown
**Q (HH:MM:SS)**: {질문 요지}
- 질문 배경 / 질문자의 의도 (추정 가능하면)

**A**: {답변 핵심}
- 답변 본문 (5~10문장으로 재구성)
- 강사가 추가로 권한 자료·다음에 다룰 주제 (있으면)
```

### 8. 실습 & 과제

강사가 부여한 과제 또는 "다음 시간까지 ..." 류 액션. 체크박스 형식 + 메타데이터. 없으면 섹션 생략.

```markdown
- [ ] {과제 제목}
  - **마감**: (강사 언급 날짜 / "(미정)")
  - **제출 형태**: (코드 / 문서 / 발표 / "(미정)")
  - **평가 기준**: (강사 명시 기준 / "(미정)")
  - **참고 자료**: (강사 언급 링크·책·논문)
```

### 9. 다음 강의 예고
강사가 언급한 다음 시간 주제·내용. 없으면 섹션 생략.

### 10. 복습 체크리스트

학습자가 강의 내용을 스스로 점검할 수 있는 질문 5~8개. 각 질문은 §4 핵심 포인트 / §6 본문에서 답할 수 있어야 합니다.

- [ ] (질문 1)
- [ ] (질문 2)
- ...

### 11. 추가 학습 추천

강사가 언급한 후속 자료 + 본문에서 자연스럽게 연결되는 다음 단계 학습 주제.

- **강사 언급 자료**: 책·논문·강의·블로그 (인용 가능한 형태로). 없으면 생략.
- **다음 학습 추천 (추론)**: 본문 내용 기반으로 자연스럽게 이어지는 주제 2~3개. `(추론)` 표기 필수.

### 12. 원문 인용

`[HH:MM:SS] "발언 내용"` — **10건까지**. 다음 우선순위로 선정:

1. 핵심 정의 (강사가 새 개념을 정의한 순간)
2. 결정적 통찰 (강사가 "이게 핵심입니다" 류로 강조)
3. 실무 팁 (강사 경험에서 우러난 노하우)
4. 자주 틀리는 함정 경고

인용은 회의록보다 비중을 약간 높게 잡되, 본문 정리가 우선. 인용으로 본문을 대신하지 말 것.

## 금지

- 강사가 명시한 정의를 다른 정의로 바꾸지 말 것
- 추정·추가 설명은 본문 안에서 `(추가 참고)` / `(추론)` 등 명시적 라벨로 분리
- 핵심 포인트를 단순 목차 나열로 채우지 말 것 — 각 항목이 독립적으로 의미를 가져야 함
- 챕터 본문이 빈약하다고 (1~2문장) 그대로 통과시키지 말 것. 강의 발화량이 적었던 챕터는 그 사실을 챕터 도입에 한 줄로 명시하고 충실히 옮길 것 (창작 금지)
- 트랜스크립트에 없는 사실 추가 금지 (할루시네이션)
