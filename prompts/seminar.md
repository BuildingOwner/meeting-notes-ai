# 세미나 / 발표 노트 (doc_type=seminar)

발표·세미나 트랜스크립트를 정리해 **내용 이해 + 실무 적용**이 가능한 노트를 작성하세요.
단순 요약이 아닌 "이 발표에서 무엇을 얻어야 하는가"를 중심으로 구성합니다.

## 출력 구조

### 1. 세미나 제목
`title` 힌트 우선, 없으면 발표 첫 단락에서 추정.

### 2. 개요

| 항목 | 내용 |
|---|---|
| 일시 | 트랜스크립트 메타·언급에서 추정; 불확실하면 "(추정)" 표기 |
| 발표자 | 트랜스크립트 단서·메타에서 추정 (불명이면 "(불명)") |
| 청중 규모 | 소규모 인터랙티브 / 대규모 강당 / 워크숍 등 톤으로 분류 |
| 주제 | 한 줄 요약 |
| 발표 배경 | 왜 이 발표가 이루어졌는지, 어떤 문제의식에서 출발했는지 1~2문장 |

### 3. 핵심 인사이트 (Takeaways)
이 발표에서 반드시 기억해야 할 **"So What"** 3~5개 불릿.
- 단순 정보 나열이 아닌, 발표자의 핵심 주장·결론·관점
- 실무나 의사결정에 적용 가능한 형태로 작성

### 4. 주요 내용
발표 본론을 흐름 순서대로 **섹션 헤딩(굵게)** 으로 구분. 각 섹션 2~5문장.
각 섹션은 "발표자가 이 부분에서 무엇을 말했는가"를 압축.

### 5. 개념·용어 정리
새로운 개념이나 정의된 용어. 없으면 섹션 생략.

| 용어 | 정의 | 발표자 맥락 |
|---|---|---|
| 용어명 | 간결한 정의 | 이 발표에서 어떤 문맥으로 사용됐는지 |

### 6. Q&A 정리
트랜스크립트에서 식별된 질문·응답만 정리. 없으면 섹션 생략.

**Q:** (질문자 불명이면 "청중") 질문 내용
**A:** 발표자 답변 요약

### 7. 후속 과제 & 참고 자료
- 발표자가 언급한 follow-up 액션, 추천 자료, 참고문헌
- 청중에게 요청된 과제나 숙제
- 없으면 섹션 생략

### 8. 원문 인용
`[HH:MM:SS] "발언 내용"` — **5건 이내**. 핵심 통찰·기억할 문장 위주.

## Notion DB 속성 매핑 (database 타겟일 때, 스키마 확인 후 적용)

| 가능한 컬럼 | 채우는 값 |
|---|---|
| 회의 제목 / Title | 위 1의 제목 |
| 날짜 / Date | 잡 생성일 |
| 회의 유형 (multi_select) | `세미나` 옵션 (스키마에 있으면) |
| 참석자 | 발표자 + 청중 규모 (예: "발표자: 김OO, 청중: ~20명") |
| 주요 결정 & 액션 아이템 | 위 7의 후속 과제 (있을 때만) |

## 금지

- 발표자가 말하지 않은 내용 추가 금지
- 청중 질문을 발표자 발언으로 혼동하지 말 것 — 화자 단서가 약하면 "Q: (청중)" 으로 표기
- 핵심 인사이트를 단순 정보 목록으로 채우지 말 것 — 발표자의 "주장"을 담아야 함
